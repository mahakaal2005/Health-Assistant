### Architecture Context
This story implements consistent styling for authentication and profile management components as part of the UI consistency enhancement. The implementation must preserve all existing authentication flows, user session management, and profile data persistence while applying design system styling.

**Source Tree Integration:** [Source: architecture/source-tree.md#new-file-organization]
- Authentication components will be placed in `auth/` package (existing structure)
- Profile management styling resources will extend existing `values/styles.xml` structure
- Settings layouts will be updated to use HealthCardComponent and design system tokens

**Technology Stack:** [Source: architecture/tech-stack.md]
- **Platform:** Android API 30-36 - maintain existing API level support
- **Language:** Kotlin - continue with existing Kotlin patterns for authentication UI components
- **UI Framework:** Material 3 - extend existing Material 3 foundation for authentication components
- **Architecture:** MVVM + Navigation Components 2.9.0 - preserve existing authentication architecture patterns
- **Database:** Room + Firebase - no changes to user data persistence or authentication flows
- **Authentication:** Firebase Auth + Google Play Services - maintain existing authentication integration
- **Dependency Injection:** Hilt 2.56.2 - continue existing DI patterns for authentication modules

**Component Architecture:** [Source: architecture/coding-standards.md#component-architecture]

### Component Specifications
**Authentication Form Components:** [Source: architecture/coding-standards.md#consistent-form-input-system]
- **Login Form:** Use HealthTextInputLayout for email and password fields with HealthFormValidation
- **Signup Form:** Use HealthTextInputLayout for all registration fields with consistent validation styling
- **Profile Editing Form:** Use HealthTextInputLayout for profile data editing with HealthFormValidation
- **Input Field Styling:** Standardized TextInputLayout styling with HealthColors for focus and error states
- **Form Validation:** HealthColors.Error for validation errors, HealthColors.Success for valid inputs

**Authentication Button Components:** [Source: architecture/coding-standards.md#standardized-button-system]
- **Primary Actions:** HealthButton.Primary for main authentication actions (Login, Sign Up, Save Profile)
- **Secondary Actions:** HealthButton.Secondary for alternative actions (Forgot Password, Cancel, Edit)
- **Tertiary Actions:** HealthButton.Tertiary for navigation actions (Switch to Login/Signup, Back)
- **Button Spacing:** HealthSpacing.Padding.large (16dp) for button content padding
- **Button Layout:** HealthSpacing.Margin.medium (12dp) for button spacing in forms

**Profile Information Components:** [Source: architecture/coding-standards.md#unified-health-card-component]
- **Profile Overview Card:** Use HealthCardComponent.Primary for main profile information display
- **Profile Section Cards:** Use HealthCardComponent.Secondary for profile data categories
- **Settings Cards:** Use HealthCardComponent.Secondary for settings category organization
- **Preference Items:** Use HealthCardComponent.Primary for individual preference settings
- **Corner Radius:** Standardized 12dp corner radius for all profile and settings cards

**Typography Hierarchy:** [Source: architecture/coding-standards.md#standardized-design-system-components]
- **Screen Titles:** HealthTypography.Title.large for authentication screen titles (Login, Sign Up, Profile)
- **Section Headers:** HealthTypography.Title.medium for profile section headers and settings categories
- **Form Labels:** HealthTypography.Body.medium for input field labels and descriptions
- **Profile Values:** HealthTypography.Body.large for profile data values (name, email, preferences)
- **Field Labels:** HealthTypography.Label.medium for profile field labels and setting descriptions
- **Error Messages:** HealthTypography.Caption for validation feedback and error messages
- **Helper Text:** HealthTypography.Caption for form helper text and setting explanations

**Error Handling and Validation:** [Source: architecture/coding-standards.md#standardized-design-system-components]
- **Error States:** HealthColors.Error for error message text and input field error outlines
- **Success States:** HealthColors.Success for successful validation indicators and confirmation messages
- **Warning States:** HealthColors.Warning for form warnings and validation hints
- **Error Positioning:** Consistent error message positioning below input fields with HealthSpacing.Margin.small
- **Validation Feedback:** Real-time validation styling with smooth color transitions

**Accessibility Requirements:** [Source: architecture/coding-standards.md#code-quality-standards]
- Minimum touch target size of 48dp for all authentication buttons and interactive elements
- Proper content descriptions for screen reader support on form fields and validation messages
- Focus states with HealthColors.Primary.default outline for keyboard navigation
- High contrast ratios for error messages and validation feedback
- Form accessibility with proper field labeling and error announcements
