# Story 1.1: Establish Core Design System Foundation

## Status
Review

## Story
**As a** developer,
**I want** centralized design system resources (colors, typography, spacing, themes),
**so that** all UI components can reference consistent styling and future updates can be managed from a single source.

## Acceptance Criteria
1. Create comprehensive color system that consolidates existing health-themed colors into semantic tokens
2. Establish typography scale using existing TextAppearance.Health styles with consistent hierarchy
3. Define spacing system with standardized dimensions for padding, margins, and component sizing
4. Update base theme to support design system tokens while maintaining Material 3 foundation
5. Create design system documentation with usage guidelines for each token

## Dev Notes

### Architecture Context
This story implements the foundational design system as outlined in the architecture documents. The design system will serve as the base for all subsequent UI consistency stories.

**Source Tree Integration:** [Source: architecture/source-tree.md#new-file-organization]
- New design system components go under `core/design/` package
- Design tokens organized in `tokens/` subdirectory
- Resource files extend existing `values/` structure
- New `design_tokens.xml` file for centralized spacing values

**Technology Stack:** [Source: architecture/tech-stack.md]
- **Platform:** Android API 30-36
- **Language:** Kotlin (latest)
- **UI Framework:** Material 3 (extend existing theme, don't replace)
- **Architecture:** MVVM + Navigation Components (preserve existing patterns)

**Component Architecture:** [Source: architecture/coding-standards.md#component-architecture]
- **HealthDesignSystem:** Centralized design tokens and component styles
- **Key Interfaces:** HealthDesignSystem.Colors, HealthDesignSystem.Typography, HealthDesignSystem.Spacing
- **Dependencies:** Extends current Material 3 theme system
- **Technology Stack:** XML resources extending existing theme structure

**Integration Requirements:**
- Must maintain existing color references without breaking current UI
- Must preserve Material 3 foundation while extending with health-focused tokens
- Must support both light and dark themes with health-focused green branding (#4CAF50 primary)
- Must not affect existing MVVM architecture, ViewModels, or navigation patterns

**Performance Constraints:** [Source: architecture/coding-standards.md#code-quality-standards]
- UI changes must not increase memory usage >15%
- Must not affect startup time >200ms
- Must maintain backward compatibility with existing user data and preferences

**Existing Color System to Consolidate:**
- health_primary: #4CAF50 (primary green)
- health_accent: #81C784 (secondary green)
- Multiple card background styles: card_background_elevated, card_background_alt, glassmorphism_card_background
- Existing TextAppearance.Health.* styles for typography

**File Naming Conventions:** [Source: architecture/source-tree.md#integration-guidelines]
- Kotlin files: PascalCase for classes, camelCase for functions
- Resource files: snake_case for XML resources
- Health prefix for all design system components
- Design system resources prefixed with "ds_" for identification

### Testing
**Testing Standards:** [Source: architecture/testing-strategy.md]
- **Framework:** JUnit 5 with MockK for unit tests
- **Test Location:** `src/test/java/com/example/health_assistant/core/design/`
- **Coverage Target:** 80%+ coverage for design system components

**Specific Testing Requirements:**
- Unit tests for color token accessibility and contrast ratios
- Unit tests for typography scaling and readability
- Unit tests for spacing consistency across different screen densities
- Integration tests to verify design system components integrate with existing fragments

**Testing Integration:** [Source: architecture/testing-strategy.md#integration-tests]

- Verify design system components integrate properly with existing fragments and activities
- Validate design system components render correctly and maintain accessibility standards
