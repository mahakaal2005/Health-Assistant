## Dev Notes

### Architecture Context
This story implements consistent styling for content discovery and article display components as part of the UI consistency enhancement. The implementation must preserve all existing content loading, search, filtering, and sharing functionality while applying design system styling.

**Source Tree Integration:** [Source: architecture/source-tree.md#new-file-organization]
- Content discovery components will be placed in `features/discover/components/` package (existing structure)
- Content display styling resources will extend existing `values/styles.xml` structure
- Article and video layouts will be updated to use HealthCardComponent and design system tokens

**Technology Stack:** [Source: architecture/tech-stack.md]
- **Platform:** Android API 30-36 - maintain existing API level support
- **Language:** Kotlin - continue with existing Kotlin patterns for content UI components
- **UI Framework:** Material 3 - extend existing Material 3 foundation for content discovery components
- **Architecture:** MVVM + Navigation Components 2.9.0 - preserve existing content architecture patterns
- **Database:** Room + Firebase - no changes to content data persistence or sync
- **Image Loading:** Coil + Glide 2.5.0 / 4.16.0 - continue for content images without changes to image loading logic
- **Video:** ExoPlayer - continue video playback without changes to video components
- **Networking:** Retrofit + OkHttp 2.9.0 / 4.12.0 - preserve API integrations without changes to network layer

**Component Architecture:** [Source: architecture/coding-standards.md#component-architecture]
- **Content Discovery Cards:** Use HealthCardComponent variants for consistent content display
- **Search Components:** Apply HealthTextInputLayout and HealthButton for consistent search UI
- **Content Detail Views:** Apply HealthTypography hierarchy for consistent content presentation
- **Integration Points:** Replaces existing content card styling while preserving functionality
- **Key Interfaces:** Content discovery components with Primary/Secondary card variants and search functionality
- **Dependencies:** Uses HealthDesignSystem color, typography, and spacing tokens from Story 1.1

**Integration Requirements:**
- Must preserve existing Guardian API integration for health articles and content
- Must maintain existing content data models and persistence logic
- Must support content search, filtering, and categorization without changes to underlying logic
- Must maintain content bookmarking and sharing functionality
- Must preserve content loading performance and caching patterns

**Performance Constraints:** [Source: architecture/coding-standards.md#code-quality-standards]
- Content discovery styling must not increase memory usage >15% or affect startup time >200ms
- Content loading and image rendering must maintain existing performance characteristics
- Content search and filtering must maintain responsive user experience during interactions

**File Naming Conventions:** [Source: architecture/source-tree.md#integration-guidelines]
- Continue existing camelCase for Kotlin files, snake_case for XML resources
- Content discovery components should use Health prefix for design system consistency
- Resource organization should extend existing values/ structure

### Component Specifications
**Content Discovery Cards:** [Source: architecture/coding-standards.md#unified-health-card-component]
- **Article Preview Cards:** Use HealthCardComponent.Primary for main article content display
- **Video Thumbnail Cards:** Use HealthCardComponent.Primary for video content with thumbnail images
- **Wellness Tip Cards:** Use HealthCardComponent.Secondary for contextual health information
- **Content Category Cards:** Use HealthCardComponent.Secondary for content organization
- **Corner Radius:** Standardized 12dp corner radius for all content discovery cards

**Content Detail View Components:** [Source: architecture/coding-standards.md#standardized-design-system-components]
- **Article Titles:** HealthTypography.Title.large for main article and video titles
- **Content Body:** HealthTypography.Body.medium for article content and video descriptions
- **Content Metadata:** HealthTypography.Label.medium for author, date, category information
- **Content Tags:** HealthTypography.Caption for tags and additional content information
- **Content Spacing:** HealthSpacing.Padding.large (16dp) for content section padding

**Search and Filtering Components:** [Source: architecture/coding-standards.md#consistent-form-input-system]
- **Search Input:** Use HealthTextInputLayout for search input fields with consistent styling
- **Filter Buttons:** HealthButton.Secondary for filter buttons and category selectors
- **Filter Options:** HealthCardComponent.Secondary for filter option cards and selections
- **Search Results:** Apply HealthTypography hierarchy for consistent search result display
- **Search Spacing:** HealthSpacing.Margin.medium (12dp) for search component spacing

**Content Categorization Components:** [Source: architecture/coding-standards.md#standardized-button-system]
- **Category Tags:** HealthButton.Tertiary for content category tags and labels
- **Category Colors:** HealthColors.Primary variants for category color coding and identification
- **Tag Text:** HealthTypography.Label.small for tag text and category labels
- **Tag Layout:** HealthSpacing.Margin.small (8dp) for tag spacing and layout consistency
- **Tag Interaction:** Minimum 48dp touch targets for category tag interactions

**Typography Hierarchy:** [Source: architecture/coding-standards.md#standardized-design-system-components]
- **Screen Titles:** HealthTypography.Title.large for content discovery screen titles (Discover, Articles)
- **Section Headers:** HealthTypography.Title.medium for content section headers and categories
- **Article Titles:** HealthTypography.Body.large for article titles in preview cards
- **Content Descriptions:** HealthTypography.Body.medium for article summaries and video descriptions
- **Content Metadata:** HealthTypography.Label.medium for author, date, and category information
- **Content Tags:** HealthTypography.Label.small for content tags and category labels
- **Helper Text:** HealthTypography.Caption for search hints and filter descriptions

**Accessibility Requirements:** [Source: architecture/coding-standards.md#code-quality-standards]
- Minimum touch target size of 48dp for all content cards and interactive elements
- Proper content descriptions for article images and video thumbnails for screen reader support
- Focus states with HealthColors.Primary.default outline for keyboard navigation
- High contrast ratios for content text and category tags
- Proper heading hierarchy with HealthTypography.Title variants for screen reader navigation
- Content accessibility with proper image alt text and video descriptions
