# Story 1.6: Unify Prescription Management UI Components

## Status
Approved

## Story
**As a** user,
**I want** consistent styling across prescription capture, storage, categorization, and detail views,
**so that** prescription management feels like a cohesive, professional health tool.

## Acceptance Criteria
1. Standardize prescription card layouts with consistent information hierarchy
2. Apply unified styling to prescription category headers and organization
3. Implement consistent camera capture UI with standardized control buttons
4. Standardize prescription detail view layouts and information presentation
5. Apply consistent form styling to prescription editing and metadata entry

## Dev Notes

### Architecture Context
This story implements consistent styling for prescription management UI components as part of the UI consistency enhancement. The implementation must preserve all existing prescription functionality while applying design system styling.

**Source Tree Integration:** [Source: architecture/source-tree.md#new-file-organization]
- Prescription components will be placed in `features/prescriptions/components/` package
- Prescription styling resources will extend existing `values/styles.xml` structure
- Prescription layouts will be updated to use HealthCardComponent and design system tokens

**Technology Stack:** [Source: architecture/tech-stack.md]
- **Platform:** Android API 30-36 - maintain existing API level support
- **Language:** Kotlin - continue with existing Kotlin patterns for UI components
- **UI Framework:** Material 3 - extend existing Material 3 foundation for prescription components
- **Architecture:** MVVM + Navigation Components 2.9.0 - preserve existing prescription architecture patterns
- **Database:** Room + Firebase - no changes to prescription data persistence or sync
- **Camera:** CameraX - maintain prescription capture functionality without changes to camera logic

**Component Architecture:** [Source: architecture/coding-standards.md#component-architecture]
- **Prescription Cards:** Use HealthCardComponent variants for consistent prescription display
- **Prescription Forms:** Apply HealthTextInputLayout and HealthFormValidation for prescription editing
- **Camera UI:** Apply HealthButton styling to camera controls while preserving CameraX functionality
- **Integration Points:** Replaces existing prescription card styling while preserving functionality
- **Key Interfaces:** Prescription display components with Primary/Secondary/Elevated card variants
- **Dependencies:** Uses HealthDesignSystem color, typography, and spacing tokens from Story 1.1

**Integration Requirements:**
- Must preserve existing prescription data models and persistence logic
- Must maintain existing prescription capture, storage, and categorization functionality
- Must support prescription image processing and storage without changes to underlying logic
- Must maintain prescription search, filtering, and organization capabilities
- Must preserve prescription sync with Firebase and local Room database

**Performance Constraints:** [Source: architecture/coding-standards.md#code-quality-standards]
- Prescription styling must not increase memory usage >15% or affect startup time >200ms
- Prescription image loading and display must maintain existing performance characteristics
- Camera capture UI must maintain responsive performance during image processing

**File Naming Conventions:** [Source: architecture/source-tree.md#integration-guidelines]
- Continue existing camelCase for Kotlin files, snake_case for XML resources
- Prescription components should use Health prefix for design system consistency
- Resource organization should extend existing values/ structure

### Component Specifications
**Prescription Card Components:** [Source: architecture/coding-standards.md#unified-health-card-component]
- **Active Prescription Cards:** Use HealthCardComponent.Primary for currently active prescriptions
- **Archived Prescription Cards:** Use HealthCardComponent.Secondary for archived or expired prescriptions
- **Prescription Detail Cards:** Use HealthCardComponent.Elevated for prescription detail view containers
- **Corner Radius:** Standardized 12dp corner radius for all prescription cards
- **Content Padding:** HealthSpacing.Padding.standard (16dp) for prescription card content

**Prescription Form Components:** [Source: architecture/coding-standards.md#consistent-form-input-system]
- **Prescription Editing Forms:** Apply HealthTextInputLayout styling for consistent input fields
- **Metadata Entry Forms:** Apply HealthTextInputLayout styling for prescription metadata fields
- **Form Validation:** Use HealthFormValidation patterns for consistent error message styling and validation feedback
- **Form Buttons:** Apply HealthButton.Primary for save actions, HealthButton.Secondary for cancel actions, HealthButton.Tertiary for delete actions

**Camera UI Components:** [Source: architecture/tech-stack.md#camera-integration]
- **Camera Capture Button:** Apply HealthButton.Primary styling to main capture button
- **Camera Settings Buttons:** Apply HealthButton.Secondary styling to settings and gallery access buttons
- **Camera Overlay:** Use HealthColors and HealthTypography tokens for camera overlay text and indicators
- **Camera Controls:** Maintain CameraX functionality while applying consistent button styling

**Typography Hierarchy:** [Source: architecture/coding-standards.md#standardized-design-system-components]
- **Prescription Names:** HealthTypography.Title.medium for prescription medication names
- **Prescription Details:** HealthTypography.Body.large for prescription dosage and instructions
- **Prescription Metadata:** HealthTypography.Body.small for timestamps, categories, and status indicators
- **Category Headers:** HealthTypography.Title.large for prescription category section headers
- **Form Labels:** HealthTypography.Label.medium for form field labels

**Accessibility Requirements:** [Source: architecture/coding-standards.md#code-quality-standards]
- Minimum touch target size of 48dp for all prescription interactions
- Proper content descriptions for screen reader support
- Focus states with HealthColors.Primary.default outline
- Keyboard navigation support for prescription selection and editing
- Camera capture accessibility with proper announcements for capture actions
