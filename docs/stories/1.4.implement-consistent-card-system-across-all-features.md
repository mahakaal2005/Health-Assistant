## Story

**I want** all content cards (health metrics, prescriptions, journal entries, articles) to have consistent visual styling,
**so that** the app feels cohesive and professional across all features.

3. Implement standardized card elevation, corner radius, and spacing patterns
4. Apply consistent typography hierarchy within all card layouts
5. Ensure card accessibility with proper focus states and screen reader support

## Dev Notes

### Architecture Context
This story implements a unified card system as part of the UI consistency enhancement. The implementation must preserve all existing functionality while applying consistent design system styling across all content cards.

**Source Tree Integration:** [Source: architecture/source-tree.md#new-file-organization]
- New HealthCardComponent will be placed in `core/design/components/` package
- Feature-specific card usage will be in existing feature modules under `components/` subdirectories
- Card styling resources will extend existing `values/styles.xml` structure

**Technology Stack:** [Source: architecture/tech-stack.md]
- **Platform:** Android API 30-36 - maintain existing API level support
- **Language:** Kotlin - continue with existing Kotlin patterns for UI components
- **UI Framework:** Material 3 - extend existing Material 3 CardView foundation
- **Architecture:** MVVM + Navigation Components 2.9.0 - preserve existing architecture patterns
- **Build System:** Gradle - no build system changes required

**Component Architecture:** [Source: architecture/coding-standards.md#component-architecture]
- **Unified Health Card Component:** Standardized card layout replacing multiple existing card styles
- **Integration Points:** Replaces card_background_elevated, card_background_alt, glassmorphism_card_background usage
- **Key Interfaces:** HealthCardView with Primary/Secondary/Elevated style variants
- **Dependencies:** Uses HealthDesignSystem color, typography, and spacing tokens from Story 1.1

**Integration Requirements:**
- Must preserve existing card content and data display functionality
- Must maintain existing card interactions (taps, long presses, navigation)
- Must support both light/dark themes with health-focused green branding
- Must not affect existing ViewModels or data binding logic

**Performance Constraints:** [Source: architecture/coding-standards.md#code-quality-standards]
- Card styling must not increase memory usage >15% or affect startup time >200ms
- Card rendering must maintain smooth scrolling performance in lists
- Must maintain existing card performance characteristics

**File Naming Conventions:** [Source: architecture/source-tree.md#integration-guidelines]
- Continue existing camelCase for Kotlin files, snake_case for XML resources
- Card components should use Health prefix for design system consistency
- Resource organization should extend existing values/ structure

### Component Specifications
**Unified Health Card Component:** [Source: architecture/coding-standards.md#unified-health-card-component]
- **Primary Variant:** Use HealthColors.Surface.primary background, HealthSpacing.Elevation.low (2dp)
- **Secondary Variant:** Use HealthColors.Surface.secondary background, HealthSpacing.Elevation.medium (4dp)
- **Elevated Variant:** Use HealthColors.Surface.primary background, HealthSpacing.Elevation.high (8dp)
- **Corner Radius:** Standardized 12dp corner radius for all card variants
- **Content Padding:** HealthSpacing.Padding.standard (16dp) for card content

**Typography Hierarchy:** [Source: architecture/coding-standards.md#standardized-design-system-components]
- **Card Titles:** HealthTypography.Title.medium for primary card headings
- **Card Content:** HealthTypography.Body.large for main card content
- **Card Metadata:** HealthTypography.Body.small for timestamps, categories, secondary info
- **Card Actions:** HealthTypography.Label.medium for button text and action labels

**Accessibility Requirements:** [Source: architecture/coding-standards.md#code-quality-standards]
- Minimum touch target size of 48dp for all card interactions
- Proper content descriptions for screen reader support
- Focus states with HealthColors.Primary.default outline
- Keyboard navigation support for card selection and actions
