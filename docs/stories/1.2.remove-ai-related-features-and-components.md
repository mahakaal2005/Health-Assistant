## Dev Notes

### Architecture Context
This story removes AI-related features as part of the UI consistency enhancement. The removal must be done carefully to avoid breaking existing functionality while cleaning up unused code and resources.

**Source Tree Integration:** [Source: architecture/source-tree.md#existing-project-structure]
- AI components likely exist across multiple packages (features/, widgets/, data/)
- Navigation graphs in res/navigation/ may contain AI destinations
- Resources in res/ directories may contain AI-related assets
- Dependency injection modules in di/ package may bind AI components

**Technology Stack:** [Source: architecture/tech-stack.md]
- **Platform:** Android API 30-36 - maintain existing API level support
- **Language:** Kotlin - follow existing Kotlin patterns for cleanup
- **Architecture:** MVVM + Navigation Components - preserve existing architecture patterns
- **Database:** Room + Firebase - clean up AI entities if they exist
- **Build System:** Gradle - no build system changes required

**Component Architecture:** [Source: architecture/coding-standards.md#component-architecture]
- **Removal Strategy:** Systematic removal starting with UI layer, then data layer
- **Dependency Analysis:** Identify all components that depend on AI features
- **Navigation Updates:** Update navigation graphs and remove AI destinations
- **Resource Cleanup:** Remove unused resources after component removal

**Integration Requirements:**
- Must not affect existing health features (prescriptions, journal, health monitoring)
- Must preserve existing MVVM architecture and ViewModels for non-AI features
- Must maintain existing Room database structure for health data
- Must not affect existing API integrations (Guardian API, health data APIs)

**Performance Constraints:** [Source: architecture/coding-standards.md#code-quality-standards]
- Removal should improve app performance by reducing unused code
- Must not affect startup time or memory usage of remaining features
- Must maintain backward compatibility with existing user data

**File Naming Conventions:** [Source: architecture/source-tree.md#integration-guidelines]
- Follow existing camelCase for Kotlin files during cleanup
- Maintain existing resource naming patterns
- Document removed components for future reference
