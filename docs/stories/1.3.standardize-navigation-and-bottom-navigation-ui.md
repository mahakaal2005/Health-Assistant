## Story

**I want** consistent navigation styling across Home, Discover, Journal, and Profile sections,
**so that** I have a cohesive navigation experience throughout the app.

## Dev Notes

### Architecture Context
This story standardizes navigation UI as part of the UI consistency enhancement. The implementation must preserve existing navigation functionality while applying consistent design system styling.

**Source Tree Integration:** [Source: architecture/source-tree.md#existing-project-structure]
- Navigation components exist in main/ package and individual feature fragments
- Bottom navigation menu defined in res/menu/bottom_nav_menu.xml
- Navigation graph defined in res/navigation/nav_main.xml
- Fragment layouts contain individual toolbar implementations

**Technology Stack:** [Source: architecture/tech-stack.md]
- **Platform:** Android API 30-36 - maintain existing API level support
- **Language:** Kotlin - continue with existing Kotlin patterns for navigation
- **UI Framework:** Material 3 - extend existing Material 3 navigation components
- **Architecture:** MVVM + Navigation Components 2.9.0 - preserve existing navigation patterns
- **Build System:** Gradle - no build system changes required

**Component Architecture:** [Source: architecture/coding-standards.md#component-architecture]
- **Standardized Navigation System:** Unified navigation styling using design system tokens
- **Integration Points:** Extends existing Material 3 navigation components without replacement
- **Key Interfaces:** BottomNavigationView styling, Toolbar standardization, Fragment transitions
- **Dependencies:** Uses HealthDesignSystem color, typography, and spacing tokens

**Integration Requirements:**
- Must preserve existing navigation functionality (Home, Discover, Journal, Profile)
- Must maintain existing navigation state persistence and lifecycle handling
- Must not affect existing ViewModels or navigation logic
- Must support both light/dark themes with health-focused green branding

**Performance Constraints:** [Source: architecture/coding-standards.md#code-quality-standards]
- Navigation styling must not increase memory usage >15% or affect startup time >200ms
- Navigation transitions must remain smooth across different device performance levels
- Must maintain existing navigation performance characteristics

**File Naming Conventions:** [Source: architecture/source-tree.md#integration-guidelines]
- Continue existing camelCase for Kotlin files, snake_case for XML resources
- Navigation styles should use Health prefix for design system consistency
- Resource organization should extend existing values/ structure
