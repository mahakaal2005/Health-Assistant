# Story 1.7: Standardize Health Monitoring and Dashboard Components

## Status
Draft

## Story
**As a** user,
**I want** consistent styling across health metrics, progress tracking, and dashboard displays,
**so that** health monitoring feels integrated and professional.

## Acceptance Criteria
1. Apply consistent chart styling and color schemes to all health metric displays
2. Standardize progress indicator appearances across different health metrics
3. Implement unified dashboard card styling for health overview information
4. Apply consistent typography to health data labels, values, and descriptions
5. Ensure health status indicators use consistent color coding and visual treatment

## Dev Notes

### Architecture Context
This story implements consistent styling for health monitoring and dashboard components as part of the UI consistency enhancement. The implementation must preserve all existing health data collection, calculation, and display functionality while applying design system styling.

**Source Tree Integration:** [Source: architecture/source-tree.md#new-file-organization]
- Health monitoring components will be placed in `features/health/components/` package
- Health dashboard styling resources will extend existing `values/styles.xml` structure
- Health chart layouts will be updated to use HealthCardComponent and design system tokens

**Technology Stack:** [Source: architecture/tech-stack.md]
- **Platform:** Android API 30-36 - maintain existing API level support
- **Language:** Kotlin - continue with existing Kotlin patterns for health UI components
- **UI Framework:** Material 3 - extend existing Material 3 foundation for health monitoring components
- **Architecture:** MVVM + Navigation Components 2.9.0 - preserve existing health metrics architecture patterns
- **Database:** Room + Firebase - no changes to health data persistence or sync
- **Charts:** MPAndroidChart - maintain health metrics visualization functionality without changes to chart logic
- **Sensors:** EnhancedHealthTracker - preserve device sensor integration for health data collection

**Component Architecture:** [Source: architecture/coding-standards.md#component-architecture]
- **Health Overview Cards:** Use HealthCardComponent variants for consistent health dashboard display
- **Progress Indicators:** Apply HealthColors.Progress tokens for consistent health status visualization
- **Chart Components:** Apply HealthColors and HealthTypography for health metric chart styling
- **Integration Points:** Replaces existing health card styling while preserving functionality
- **Key Interfaces:** Health dashboard components with Primary card variants and progress indicators
- **Dependencies:** Uses HealthDesignSystem color, typography, and spacing tokens from Story 1.1

**Integration Requirements:**
- Must preserve existing health data models (HealthMetrics, HealthMetric) and persistence logic
- Must maintain existing health data collection from device sensors via EnhancedHealthTracker
- Must support health metric calculations and progress tracking without changes to underlying logic
- Must maintain health data sync with Firebase and local Room database
- Must preserve health notification functionality for step milestones

**Performance Constraints:** [Source: architecture/coding-standards.md#code-quality-standards]
- Health monitoring styling must not increase memory usage >15% or affect startup time >200ms
- Health chart rendering and progress calculations must maintain existing performance characteristics
- Health data collection from sensors must maintain responsive performance during updates

**File Naming Conventions:** [Source: architecture/source-tree.md#integration-guidelines]
- Continue existing camelCase for Kotlin files, snake_case for XML resources
- Health monitoring components should use Health prefix for design system consistency
- Resource organization should extend existing values/ structure

### Component Specifications
**Health Dashboard Cards:** [Source: architecture/coding-standards.md#unified-health-card-component]
- **Health Overview Card:** Use HealthCardComponent.Primary for main health summary display
- **Progress Tracking Cards:** Use HealthCardComponent.Primary for weekly progress displays (steps, calories)
- **Wellness Tip Card:** Use HealthCardComponent.Secondary for contextual health information
- **Corner Radius:** Standardized 12dp corner radius for all health dashboard cards
- **Content Padding:** HealthSpacing.Padding.xl (24dp) for health dashboard card content

**Health Chart Components:** [Source: architecture/tech-stack.md#charts-integration]
- **Bar Charts:** Apply HealthColors.Progress tokens for consistent health metric visualization
- **Chart Background:** Use transparent background with HealthColors grid and axis styling
- **Chart Legend:** Apply HealthTypography.Label.medium for chart labels and descriptions
- **Chart Values:** Apply HealthTypography.Body.large for health metric values and statistics

**Progress Indicator Components:** [Source: architecture/coding-standards.md#standardized-design-system-components]
- **Triple Ring Progress:** Apply HealthColors.Progress.orange (steps), green (calories), blue (heart points)
- **Linear Progress Indicators:** Use HealthColors.Progress variants for weekly goal progress
- **Progress Text:** Apply HealthTypography.Caption for progress percentages and goal statistics
- **Progress Sizing:** Use HealthSpacing tokens for consistent progress indicator dimensions

**Typography Hierarchy:** [Source: architecture/coding-standards.md#standardized-design-system-components]
- **Section Titles:** HealthTypography.Title.large for health dashboard section headers (Health Overview, My Progress)
- **Metric Values:** HealthTypography.Body.large for health data values (steps count, calories, heart points)
- **Metric Labels:** HealthTypography.Label.medium for health metric labels and descriptions
- **Summary Statistics:** HealthTypography.Caption for progress percentages, averages, and goal statistics
- **Chart Labels:** HealthTypography.Label.small for chart axis labels and legends

**Health Status Color Coding:** [Source: architecture/coding-standards.md#standardized-design-system-components]
- **Steps Indicators:** HealthColors.Progress.orange for steps progress rings, charts, and status indicators
- **Calories Indicators:** HealthColors.Progress.green for calorie progress rings, charts, and status indicators
- **Heart Points Indicators:** HealthColors.Progress.blue for heart points progress rings, charts, and status indicators
- **Goal Achievement:** HealthColors.Success for completed goals and milestones
- **Warning States:** HealthColors.Warning for low activity or missed goals

**Accessibility Requirements:** [Source: architecture/coding-standards.md#code-quality-standards]
- Minimum touch target size of 48dp for all health monitoring interactions
- Proper content descriptions for screen reader support on charts and progress indicators
- Focus states with HealthColors.Primary.default outline for keyboard navigation
- High contrast ratios for health status indicators and progress visualization
- Chart accessibility with proper data announcements for screen readers
